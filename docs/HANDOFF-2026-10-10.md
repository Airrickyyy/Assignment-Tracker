### 6. Diagnosed why notifications weren't firing

**Symptom:** Test button in Settings works (OS permission granted), but creating a new assignment never triggers a notification.

**Diagnostic approach:** Added targeted `console.log` calls at the top of the `useEffect` and inside `fire()` to see where execution stopped.

**Log output:**
```
[notif] effect fired — uid: null enabled: false loaded: false seeded: false perm: granted
[notif] effect fired — uid: null enabled: false loaded: false seeded: false perm: granted
[notif] effect fired — uid: …c543 enabled: false loaded: false seeded: false perm: granted
[notif] effect fired — uid: …c543 enabled: false loaded: true seeded: false perm: granted
```

**Root cause:** `enabled: false` on every single run. The hook always returns early at `if (!enabled) return`. The `desktopNotificationsEnabled` setting was `false` the entire time.

**Why the Test button worked:** The Test button in `SettingsView.jsx` calls `new Notification()` directly in a click handler. It does NOT check `settings.desktopNotificationsEnabled`. So it fires regardless of the toggle.

**Why the toggle was off:** Notification permission was already `granted` in the browser before the user explicitly navigated to Settings and clicked "Request Permission". The `requestPermission()` flow auto-enables the toggle when permission is granted on that button click. But if permission was pre-existing, the Settings page renders the "granted" UI with the toggle defaulting to `false` (from `DEFAULT_SETTINGS`). The user saw the Test button work and assumed notifications were active.

### 7. Fixed: `loadSettings()` auto-enable when permission is pre-granted

**File:** `src/lib/storage.js`

**Before:**
```js
export function loadSettings() {
  const raw = localStorage.getItem(KEYS.settings)
  const parsed = tryParse(raw)
  if (!parsed || typeof parsed !== 'object') return { ...DEFAULT_SETTINGS }
  return { ...DEFAULT_SETTINGS, ...parsed }
}
```

**After:**
```js
export function loadSettings() {
  const raw = localStorage.getItem(KEYS.settings)
  const parsed = tryParse(raw)
  const stored = (parsed && typeof parsed === 'object') ? parsed : {}
  const settings = { ...DEFAULT_SETTINGS, ...stored }
  // If browser permission is already granted but the user never explicitly
  // set the in-app toggle (key absent from localStorage), default it to on.
  if (
    !('desktopNotificationsEnabled' in stored) &&
    typeof Notification !== 'undefined' &&
    Notification.permission === 'granted'
  ) {
    settings.desktopNotificationsEnabled = true
  }
  return settings
}
```

**Logic:**
- If `desktopNotificationsEnabled` was never stored → user hasn't made a choice → check permission → auto-enable if granted
- If stored as `false` → user explicitly turned it off (or was set by previous bug) → respect it
- If stored as `true` → already enabled → no change needed

**Limitation:** Does NOT fix users whose localStorage has `desktopNotificationsEnabled: false` due to the previous sign-out reset bug (the value was stored explicitly as false even though the user never made that choice). For those users, the one-time fix is to go to Settings → Notifications and flip the toggle on. After that, it persists correctly.

## Notification system architecture summary (for reference)

```
App.jsx
  ├── assignments (state) ──────────────────────────────────┐
  ├── notifTick (5-min interval) ──────────────────────────┤
  ├── reminders = useMemo(deriveReminders, [assignments, notifTick])
  │     ├── upcoming: due today or within 48h, not completed
  │     └── overdue:  due before today, not completed
  │
  └── useDesktopNotifications({ reminders, enabled, sessionUserId, assignmentsLoaded, onNavigate })
        ├── prevUserRef: resets sentRef/seededRef on user change
        ├── Guards: sessionUserId, enabled, API available, permission granted
        ├── First qualifying run (seededRef=false, assignmentsLoaded=true):
        │     → adds all current IDs to sentRef, sets seededRef=true, returns (no notification)
        └── Subsequent runs (seededRef=true):
              → for each new ID not in sentRef: fire() → new Notification()

Settings toggle (desktopNotificationsEnabled)
  ├── Stored in localStorage only (NOT synced to Supabase)
  ├── Preserved across sign-out via: setSettings(prev => ({ ...DEFAULT_SETTINGS, desktopNotificationsEnabled: prev.desktopNotificationsEnabled }))
  └── Auto-enabled on load if: permission=granted AND key was never stored in localStorage
```
